# Ночной QA-проход — 18.10.2026

Коротко: починил падение профиля, ускорил первую загрузку втрое и убрал
причину, по которой Docker-сборка на Linux падала бы целиком.

---

## 1. Починен реальный баг в профиле (React hooks)

`frontend/src/pages/ProfilePage.jsx`

`useMemo` для купленных рамок вызывался **после** раннего `return`
`if (!user)`. Пока пользователь не загружен — хуков на один меньше, после
загрузки — на один больше. React на таком переходе бросает
«Rendered more hooks than during the previous render» и размонтирует экран.

- `ownedFrames` перенесён выше раннего return;
- заодно закрыт warning `exhaustive-deps` у эффекта синхронизации таба с URL
  (в зависимости добавлен `tab`).

Это был единственный **error** в `npm run lint`. Сейчас линтер ошибок не даёт.

## 2. Ленивая загрузка страниц: первый экран легче в 3 раза

`frontend/src/App.jsx`, `frontend/src/components/layout/AppLayout.jsx`

Раньше весь фронтенд лежал в одном чанке — **1 313 КБ (357 КБ gzip)**.
Теперь страницы подключаются через `React.lazy` + `Suspense`, а в стартовый
бандл входит только каркас (роутер, стор, layout).

| | было | стало |
|---|---|---|
| JS на первом экране | 357 КБ gzip | **120 КБ gzip** |
| Страница статистики (recharts) | в общем чанке | отдельные 104 КБ gzip по требованию |
| Канбан, магазин, дашборд, профиль | в общем чанке | отдельные чанки по требованию |

Дополнительно `Suspense` стоит **внутри** `AppLayout` вокруг `<Outlet />`:
при первом переходе на тяжёлую страницу сайдбар и топбар не исчезают,
подменяется только контентная область.

Проверено: `npm run build` — 30+ чанков, `vite preview` отдаёт `index.html`
и стартовый ассет с кодом 200.

## 3. Регистр импортов: сборка в Docker на Linux была обречена

Windows не различает `../Task` и `../task`, Linux — различает. В проекте
после переименования папок в нижний регистр осталось **58 импортов** со
старым регистром (`../Modal/Modal`, `../components/Shop/AccentCard`,
`../Task/TaskDetailModal` и т.д.). Локально всё собиралось, а `docker build`
на Linux-контейнере упал бы на «Could not resolve».

- все 58 спецификаторов приведены к реальному регистру файлов;
- `frontend/src/pages/SortableBoardCard.jsx` — мёртвая копия компонента,
  импортировавшая несуществующий `./BoardCard`, удалена (в `components/board`
  живёт рабочая версия);
- добавлен скрипт-страж `frontend/scripts/check-import-case.mjs`
  и команда `npm run check:imports`: она находит и битые пути, и
  несовпадения регистра, и умеет чинить (`node scripts/check-import-case.mjs --fix`).

Сейчас проверка: `OK: регистр всех относительных импортов совпадает с файлами`.

## 4. ErrorBoundary: вместо белого экрана — понятное сообщение

`frontend/src/components/common/ErrorBoundary.jsx` + стили в `index.css`.

Любая ошибка рендера (например, в новом виджете дашборда) раньше
размонтировала всё приложение. Теперь показывается карточка «Что-то
сломалось» с текстом ошибки и кнопками «Обновить страницу» /
«Попробовать снова», а детали уходят в консоль.

## Что осталось (на будущее, не трогал)

- **`npm run lint` — 60+ warning'ов** `no-unused-expressions` в
  `ListView.jsx` / `CompactView.jsx` / `TaskDetailModal.jsx`: это выражения
  вида `onOpenTask && onOpenTask(id)`, функционально корректные, но лучше
  заменить на `if`. Плюс несколько `set-state-in-effect` — их стоит
  переписать на производные значения.
- **`docker build` не проверен**: Docker Desktop на машине выключен.
  После фикса регистра он должен пройти, но реальную сборку стоит запустить.
- **Незакоммиченные изменения** (79 файлов + новые миграции 022/023,
  дашборд, Docker-обвязка) я не коммитил — это твоя зона решения.
- Бандл CSS — один файл 230 КБ (33 КБ gzip); при желании можно разрезать
  по страницам, но выигрыш уже небольшой.
