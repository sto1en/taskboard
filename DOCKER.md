# TaskBoard — развёртывание в Docker

Приложение состоит из трёх частей, которые поднимаются одной командой:

| Сервис     | Что это                         | Наружу     |
|------------|---------------------------------|------------|
| `db`       | PostgreSQL 16                   | нет        |
| `backend`  | Spring Boot API (Java 21)       | нет        |
| `frontend` | nginx + собранный React-SPA     | да, порт `FRONTEND_PORT` |

Наружу открыт **только** frontend. Он же проксирует `/api` и `/uploads`
на backend внутри docker-сети, поэтому отдельный домен для API не нужен.

---

## 1. Что нужно на сервере

- **Docker Engine** 20.10+ и **Docker Compose v2** (`docker compose`, не `docker-compose`).
- Свободный порт (по умолчанию 80).
- Минимум ~2 ГБ RAM: сборка backend (Maven) — самая тяжёлая операция.

Установка Docker на Ubuntu/Debian:

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER      # затем перелогиниться
```

Проверка:

```bash
docker --version && docker compose version
```

---

## 2. Как перенести проект

Скопируйте всю папку проекта на сервер (кроме `node_modules`, `target`,
`dist` — они не нужны, всё собирается внутри образов). Например:

```bash
# с локальной машины
scp -r ./taskBoard user@SERVER:/opt/taskBoard
```

или через git:

```bash
git clone <ваш-репозиторий> /opt/taskBoard
```

---

## 3. Настройка секретов

В корне проекта создайте `.env` из шаблона:

```bash
cd /opt/taskBoard
cp .env.docker.example .env
nano .env
```

Обязательно поменяйте:

- `DB_PASSWORD` — пароль к базе;
- `APP_JWT_SECRET` — длинный случайный секрет (>= 32 символов);
- `FRONTEND_PORT` — если 80 занят, поставьте другой (например, 8080).

Сгенерировать секрет JWT:

```bash
openssl rand -base64 48
```

> Без `DB_PASSWORD` и `APP_JWT_SECRET` compose намеренно не стартует —
> это защита от запуска на дефолтных секретах.

---

## 4. Запуск

```bash
cd /opt/taskBoard
docker compose up -d --build
```

Первый запуск занимает несколько минут (скачиваются образы и собираются
backend/frontend). Дальше — секунды.

Проверить, что всё поднялось:

```bash
docker compose ps
docker compose logs -f
```

Все три сервиса должны быть в статусе `running`/`healthy`. Сайт откроется
по адресу `http://SERVER_IP` (или `http://SERVER_IP:FRONTEND_PORT`).

> Миграции БД (Liquibase) и справочники (достижения, магазин, MIME-типы)
> накатываются автоматически при первом старте backend.

---

## 5. Регистрация первого пользователя

После старта откройте сайт и зарегистрируйтесь. Первый созданный пользователь
автоматически получает права администратора (это делает миграция `018`).

Сразу после регистрации:
1. Создайте доску (кнопка «+» на странице **Доски**) — при создании доски
   автоматически создаётся её основной проект «main».
2. В **Профиле → Рабочее пространство** включите «Открывать доску при запуске»
   и выберите доску, если хотите попадать на неё сразу вместо календаря.

---

## 6. Данные и тома

Данные живут в именованных томах Docker и переживают пересборку контейнеров:

- `pgdata` — база данных;
- `uploads` — загруженные пользователями файлы.

`docker compose down` **не удаляет** тома. Полное удаление данных — только
через `docker compose down -v` (осторожно, это сотрёт базу и загрузки).

Бэкап базы:

```bash
docker compose exec db pg_dump -U postgres taskboard > backup.sql
```

Восстановление:

```bash
cat backup.sql | docker compose exec -T db psql -U postgres -d taskboard
```

---

## 7. Обновление версии

```bash
cd /opt/taskBoard
git pull                          # или заново скопировать исходники
docker compose up -d --build      # пересоберёт изменённые образы
docker image prune -f             # опционально: подчистить старые слои
```

Тома с данными при этом не трогаются.

---

## 8. HTTPS (рекомендуется для прода)

Самый простой путь — поставить перед compose-фронтендом Caddy или nginx
с Let's Encrypt, либо использовать caddy как отдельный контейнер с
`reverse_proxy frontend:80`. Если планируете — сделайте так, чтобы
`FRONTEND_PORT` смотрел только на localhost:

```yaml
ports:
  - "127.0.0.1:${FRONTEND_PORT:-80}:80"
```

---

## 9. Если что-то не работает

**Порт 80 занят** — поменяйте `FRONTEND_PORT` в `.env` и
`docker compose up -d`.

**Backend падает с ошибкой подключения к БД** — проверьте `docker compose logs backend`.
Чаще всего причина в неверном `DB_PASSWORD` или в том, что `db` ещё не
успел подняться (backend ждёт `service_healthy`, так что обычно достаточно
просто перезапустить: `docker compose restart backend`).

**`/api` возвращает 502** — backend ещё не поднялся либо упал. Смотрите
`docker compose logs backend`.

**Не грузятся картинки/аватары** — проверьте, что том `uploads` примонтирован
и backend пишет в `/app/uploads` (переменная `UPLOAD_DIR`).

**Долго собирается образ backend** — это нормально: Maven скачивает
зависимости. Повторная сборка идёт из кэша и заметно быстрее.

---

## Локальная разработка (не Docker)

Для разработки ничего не менялось:

- backend запускается как обычно (порт `8082`, БД `localhost:5432`);
- frontend: `npm run dev` (порт `5173`, Vite проксирует `/api` на `8082`).

Docker-файлы в этом сценарии не используются. Хостовой `nginx.conf` в корне
(для запуска без Docker на сервере) — используйте только если не хотите
Docker; в нём нужно поправить путь в `root`.
